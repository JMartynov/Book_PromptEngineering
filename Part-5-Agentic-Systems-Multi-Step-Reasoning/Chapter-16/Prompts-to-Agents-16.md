# Chapter 16: From Prompts to Agents

## Introduction: The "Goal-Oriented" Shift

In the first half of this book, we've focused on "Input -> Output" systems. You give the LLM a prompt, and it gives you a response. This is a "Chatbot" model. But in 2026, the real value is in **AI Agents**.

An AI Agent is a system that isn't just a smarter chatbot; it is a **Goal-Oriented System**. You give it an objective (e.g., "Research the competitors of our new product and email a 3-bullet summary to the CEO"), and it plans the steps, selects the right tools (web search, email API), evaluates its own progress, and executes multiple sub-tasks autonomously to reach that goal.

---

## Deep Technical Analysis: The Agentic Architecture

The shift from "Static Prompts" to "Dynamic Agents" is built on four architectural layers:

### 1. The Planner (The Pre-frontal Cortex)
Instead of executing a prompt immediately, the agent uses a **Planning Module** to decompose the high-level goal into a directed graph of sub-tasks. Research into **Plan-and-Execute** patterns has shown that separate "Planning" and "Execution" steps reduce hallucinations by 30% because the model isn't trying to do two things (reasoning and acting) at once.

### 2. The Tool Interface (The Effectors)
Agents use **Function Calling** to interact with the world. In 2026, we treat tools as "Skills." Each tool is defined with a strict JSON schema (Pydantic model) that describes what it does and what arguments it needs. The LLM acts as the "Dispatcher," deciding which skill to invoke based on the current state of the plan.

### 3. Persistent Memory (Episodic & Long-Term)
A standard prompt is "Stateless." An agent is **Stateful**. It maintains:
-   **Short-Term Memory:** The history of the current task (thoughts, tool results).
-   **Long-Term Memory:** Learnings from previous tasks, stored in a Vector DB.
Modern agents use **Reflection** to summarize their short-term memory into long-term insights, preventing the context window from becoming overloaded.

### 4. The Executor/Critic Loop (Self-Correction)
This is the "Engine" of autonomy. The agent follows the **ReAct** (Reason + Act) pattern. After each action, it "Observes" the result and "Critiques" whether it is closer to the goal. If a tool fails (e.g., a 404 error from a website), the Critic triggers a "Re-planning" step to find an alternative path.

---

## Why Agents Solve Real-World Problems

In practice, AI Agents solve several critical production issues:
-   **Handling Open-Ended Tasks:** You can't write a single prompt for "Fix this bug in the codebase." An agent can browse the files, run tests, identify the error, and write the fix.
-   **Tool Interoperability:** Agents act as the "Natural Language API" for your entire software stack, connecting your CRM, database, and email server without needing 100 separate manual integrations.
-   **Cost-Efficient Autonomy:** Instead of a human spending 2 hours on a task, an agent can do it in 2 minutes for $0.50.

### Example 1: The "Hierarchical Planner"
**Problem:** High-level user objectives (e.g., "Audit AWS infrastructure and secure open buckets") are too complex and ambiguous for single-step execution.
**Solution:** Decompose the goal into a deterministic, validated multi-step plan using Pydantic schemas before executing any tool actions.

```python
import json
from typing import List, Optional
from pydantic import BaseModel, Field


class Task(BaseModel):
    """A discrete, actionable sub-goal within a larger plan."""
    id: int = Field(..., description="Unique sequential identifier for the task")
    action: str = Field(..., description="Actionable technical operation to perform")
    tool_required: str = Field(..., description="Name of the registered tool to invoke")
    expected_output: str = Field(..., description="Description of the expected artifact or result")
    depends_on: List[int] = Field(default_factory=list, description="IDs of preceding prerequisite tasks")


class MissionPlan(BaseModel):
    """Structured execution plan generated by the hierarchical planner."""
    goal: str = Field(..., description="The verified primary objective")
    security_clearance_required: bool = Field(False, description="Whether privileged operations are present")
    steps: List[Task] = Field(..., description="Ordered list of tasks to accomplish the goal")


def generate_plan(user_goal: str) -> MissionPlan:
    """
    Decomposes a complex objective into a validated MissionPlan.
    In production, this queries an LLM configured with structured JSON outputs.
    """
    # Realistic planner prompt payload
    system_prompt = (
        "You are an expert Autonomous Systems Planner. Decompose the given user goal into "
        "a sequence of precise, atomic tasks adhering to the MissionPlan schema. "
        "Ensure all tool names correspond to registered tools: ['s3_scanner', 'iam_checker', 'remediation_bot']."
    )

    # Simulated structured output response matching OpenAI / Instructor JSON Schema mode
    simulated_llm_response = {
        "goal": user_goal,
        "security_clearance_required": True,
        "steps": [
            {
                "id": 1,
                "action": "Scan all AWS S3 buckets for public read/write ACLs",
                "tool_required": "s3_scanner",
                "expected_output": "List of bucket ARNs with public ACLs",
                "depends_on": []
            },
            {
                "id": 2,
                "action": "Evaluate IAM roles attached to flagged public buckets",
                "tool_required": "iam_checker",
                "expected_output": "IAM policy audit report for identified buckets",
                "depends_on": [1]
            },
            {
                "id": 3,
                "action": "Apply private ACLs and block public access policies",
                "tool_required": "remediation_bot",
                "expected_output": "Remediation confirmation status",
                "depends_on": [1, 2]
            }
        ]
    }

    # Validate against Pydantic model (ensuring runtime safety)
    validated_plan = MissionPlan.model_validate(simulated_llm_response)
    return validated_plan


if __name__ == "__main__":
    goal = "Audit S3 buckets for public access and enforce zero-trust policies"
    plan = generate_plan(goal)
    print(f"Goal: {plan.goal}")
    print(f"Privileged Access Needed: {plan.security_clearance_required}")
    print(f"Total Steps: {len(plan.steps)}")
    for step in plan.steps:
        print(f"  [{step.id}] {step.action} (Tool: {step.tool_required}, Depends on: {step.depends_on})")
```

**Developer Explanation:**
- **Libraries Used:** `pydantic` (v2) for runtime validation and JSON Schema enforcement.
- **How It Works:** Rather than letting the agent execute actions spontaneously, the `generate_plan` module isolates the reasoning phase. It outputs a `MissionPlan` containing dependency-linked `Task` nodes.
- **Expected Output:** A validated, structured DAG of tasks with explicit dependencies (`depends_on`), preventing circular logic and missing prerequisites.
- **Why This Approach:** Decoupling planning from tool invocation eliminates hallucinated tool sequences and limits context-window degradation during multi-stage missions.

### Example 2: Typed Tool Definitions (The "Skill" Pattern)
**Problem:** LLMs frequently produce malformed parameters, out-of-range numerical values, or invalid resource identifiers when calling external APIs.
**Solution:** Enforce runtime argument validation with Pydantic's `@validate_call` and exportable JSON schemas for tool registries.

```python
import json
from typing import Any, Dict, List
from pydantic import BaseModel, Field, ValidationError, validate_call


class FetchLogsInput(BaseModel):
    """Schema definition for log query requests."""
    resource_arn: str = Field(
        ...,
        pattern=r"^arn:aws:[a-z0-9-]+:[a-z0-9-]*:[0-9]{12}:.+",
        description="The full AWS ARN of the target resource"
    )
    limit: int = Field(
        default=50,
        ge=1,
        le=500,
        description="Maximum number of log events to fetch (1-500)"
    )
    filter_pattern: str = Field(
        default="ERROR",
        description="Log stream filter expression (e.g. 'ERROR', 'WARN')"
    )


@validate_call
def fetch_cloud_logs(resource_arn: str, limit: int = 50, filter_pattern: str = "ERROR") -> Dict[str, Any]:
    """
    Executes a typed tool query to fetch access logs for an AWS resource.
    Input arguments are verified at runtime before the business logic runs.
    """
    # Simulated cloud provider API call
    return {
        "status": "success",
        "resource": resource_arn,
        "returned_records": limit,
        "filter": filter_pattern,
        "logs": [
            f"[2026-08-17T12:00:0{i}Z] {filter_pattern}: Unauthorized access attempt detected on {resource_arn}"
            for i in range(min(limit, 3))
        ]
    }


def get_tool_json_schema() -> Dict[str, Any]:
    """Exports the tool signature as an OpenAI/Anthropic-compatible function tool definition."""
    return {
        "type": "function",
        "function": {
            "name": "fetch_cloud_logs",
            "description": "Fetches access logs for a specific cloud resource with strict validation.",
            "parameters": FetchLogsInput.model_json_schema()
        }
    }


if __name__ == "__main__":
    # 1. Export schema for the model
    tool_schema = get_tool_json_schema()
    print("Exported JSON Schema for LLM Function Calling:")
    print(json.dumps(tool_schema, indent=2))

    # 2. Valid invocation
    valid_arn = "arn:aws:s3:us-east-1:123456789012:bucket/secure-vault"
    result = fetch_cloud_logs(resource_arn=valid_arn, limit=2, filter_pattern="ERROR")
    print(f"\nTool Execution Result:\n{json.dumps(result, indent=2)}")

    # 3. Invalid invocation caught by Pydantic before reaching the underlying API
    try:
        fetch_cloud_logs(resource_arn="invalid-bucket-string", limit=1000)
    except ValidationError as e:
        print("\nRuntime Type Validation Error caught successfully:")
        print(f"Error count: {len(e.errors())}, Details: {e.errors()[0]['msg']}")
```

**Developer Explanation:**
- **Libraries Used:** `pydantic` (`validate_call`, `Field`, `BaseModel`, `ValidationError`).
- **How It Works:** `@validate_call` decorates the actual Python function, while `model_json_schema()` extracts the JSON schema passed to LLM function-calling interfaces.
- **Expected Output:** Malformed parameters (like out-of-range limits or invalid ARNs) are rejected instantly at the boundary before executing network calls.
- **Why This Approach:** Prevents garbage parameters generated by hallucinations from causing database corruptions or triggering expensive upstream cloud billing.

### Example 3: The ReAct Loop (Reasoning in Public)
**Problem:** Black-box agents that jump straight into tool calls are impossible to debug, audit, or steer when an action produces an error.
**Solution:** Implement an explicit ReAct (Reasoning + Acting) loop with deterministic parsing of `THOUGHT`, `ACTION`, and `OBSERVATION` steps.

```python
import re
from typing import Callable, Dict, Tuple


# Define concrete tool handlers
def query_database(table: str) -> str:
    tables = {
        "users": "user_id=101, name=Alice, role=developer | user_id=102, name=Bob, role=contractor",
        "access_logs": "log_id=901, user_id=102, action=DELETE_DATABASE_BACKUP, status=BLOCKED"
    }
    return tables.get(table.strip().lower(), f"Error: Table '{table}' not found.")


def revoke_user_access(user_id: str) -> str:
    return f"Success: Revoked all credentials and active sessions for user_id={user_id.strip()}."


# Tool registry mapping tool names to functions
TOOL_REGISTRY: Dict[str, Callable[[str], str]] = {
    "query_database": query_database,
    "revoke_user_access": revoke_user_access
}


class ReActAgent:
    """A deterministic ReAct loop executor with thought parsing and tool dispatch."""

    def __init__(self, tools: Dict[str, Callable[[str], str]], max_iterations: int = 5):
        self.tools = tools
        self.max_iterations = max_iterations

    def _parse_action(self, llm_text: str) -> Tuple[str, str]:
        """Extracts tool name and argument from 'ACTION: tool_name(arg)' format."""
        match = re.search(r"ACTION:\s*(\w+)\((.*?)\)", llm_text)
        if match:
            return match.group(1), match.group(2)
        return "", ""

    def run(self, goal: str) -> str:
        trajectory = []
        step = 0

        # Initial prompt context
        print(f"=== Starting ReAct Agent Mission ===")
        print(f"Goal: {goal}\n")

        # Simulated trajectory of an LLM thinking and acting across steps
        simulated_llm_steps = [
            "THOUGHT: I need to check the access logs table to see if contractor accounts triggered alerts.\nACTION: query_database(access_logs)",
            "THOUGHT: The logs show user_id 102 attempted an unauthorized backup deletion. I must immediately revoke user 102's access.\nACTION: revoke_user_access(102)",
            "THOUGHT: Access has been revoked and recorded. Mission is complete.\nFINAL ANSWER: User 102 (Bob) attempted unauthorized deletion; credentials have been revoked."
        ]

        for step_text in simulated_llm_steps:
            step += 1
            print(f"--- Step {step} ---")
            print(step_text)

            if "FINAL ANSWER:" in step_text:
                final_answer = step_text.split("FINAL ANSWER:")[1].strip()
                return final_answer

            tool_name, tool_arg = self._parse_action(step_text)
            if tool_name in self.tools:
                observation = self.tools[tool_name](tool_arg)
            else:
                observation = f"Error: Tool '{tool_name}' not available."

            print(f"OBSERVATION: {observation}\n")
            trajectory.append((step_text, observation))

            if step >= self.max_iterations:
                return "Aborted: Max iteration limit reached."

        return "Completed without final answer."


if __name__ == "__main__":
    agent = ReActAgent(tools=TOOL_REGISTRY)
    result = agent.run("Investigate suspicious contractor activity and remediate immediately.")
    print(f"Result: {result}")
```

**Developer Explanation:**
- **Libraries Used:** `re` for deterministic action-syntax parsing, standard typing and function dispatching.
- **How It Works:** Every step forces the agent to document its internal hypothesis (`THOUGHT`), declare an operation (`ACTION`), receive the real system response (`OBSERVATION`), and iterate until outputting `FINAL ANSWER`.
- **Expected Output:** A transparent execution trace showing every intermediate hypothesis and tool output leading to the final decision.
- **Why This Approach:** Enables complete observability and post-incident auditing for autonomous workflows.

### Example 4: Agentic Self-Correction (The "Critic")
**Problem:** LLMs can produce answers that look plausible but fail key domain requirements or miss critical edge cases.
**Solution:** Establish a dual-agent Generator-Critic loop where a secondary evaluation node verifies outputs against criteria before returning.

```python
from typing import List, Tuple
from pydantic import BaseModel, Field


class CriticReview(BaseModel):
    """Structured critique feedback model."""
    passed: bool = Field(..., description="True if output meets all acceptance criteria")
    score: float = Field(..., ge=0.0, le=1.0, description="Quality score between 0.0 and 1.0")
    missing_elements: List[str] = Field(default_factory=list, description="Specific missing requirements")
    remediation_guidance: str = Field(..., description="Actionable instructions for the generator to fix flaws")


def evaluate_output(goal: str, candidate_output: str, required_keys: List[str]) -> CriticReview:
    """
    Evaluates candidate output against strict structural and content standards.
    Combines rule-based checks with structured reasoning.
    """
    missing = [req for req in required_keys if req.lower() not in candidate_output.lower()]
    passed = len(missing) == 0

    if passed:
        return CriticReview(
            passed=True,
            score=1.0,
            missing_elements=[],
            remediation_guidance="Output satisfies all requirements."
        )
    else:
        return CriticReview(
            passed=False,
            score=0.4,
            missing_elements=missing,
            remediation_guidance=f"Ensure the response explicitly addresses: {', '.join(missing)}"
        )


def self_correcting_pipeline(goal: str, required_criteria: List[str]) -> str:
    """Executes generator attempts with iterative critic feedback loops."""
    # Attempt 1: Incomplete response
    draft = "Summary: We scanned the database and everything looks fine."
    
    for attempt in range(1, 4):
        print(f"\n[Attempt {attempt}] Candidate Draft:\n  '{draft}'")
        review = evaluate_output(goal, draft, required_criteria)
        print(f"[Critic Review] Passed: {review.passed} | Score: {review.score}")

        if review.passed:
            print("[Critic] Output approved!")
            return draft

        print(f"[Critic Guidance] Missing: {review.missing_elements}. {review.remediation_guidance}")
        # Simulated generator refinement incorporating critic guidance
        draft = (
            "Summary: Completed full database audit on cluster 'prod-db-01'. "
            "Public access: Disabled. Encryption: AES-256 enabled. Backup policy: Retained for 30 days."
        )

    return draft


if __name__ == "__main__":
    objective = "Produce an infrastructure compliance summary for prod-db-01."
    criteria = ["Encryption", "Public access", "Backup policy"]
    final_output = self_correcting_pipeline(objective, criteria)
    print(f"\nFinal Validated Output:\n{final_output}")
```

**Developer Explanation:**
- **Libraries Used:** `pydantic` for structured evaluation reporting.
- **How It Works:** A dedicated critic evaluates outputs against deterministic checklists and semantic criteria. If flaws are found, specific remediation guidance is fed back into the next generation attempt.
- **Expected Output:** The loop auto-corrects deficient drafts until the output meets quality standards.
- **Why This Approach:** Prevents low-quality generations from escaping into production systems by enforcing an automated verification gate.

### Example 5: Episodic Memory with "Thread IDs"
**Problem:** Stateless LLM interactions forget earlier decisions, requiring the user or orchestrator to resend massive context histories.
**Solution:** Persist conversation episodes into an indexed memory store and dynamically query relevant past steps using thread identifiers.

```python
import sqlite3
import json
from datetime import datetime, timezone
from typing import Dict, List, Optional
from pydantic import BaseModel, Field


class MemoryRecord(BaseModel):
    """Schema for stored agent memory events."""
    thread_id: str
    step_number: int
    action_type: str
    content: str
    timestamp: str = Field(default_factory=lambda: datetime.now(timezone.utc).isoformat())


class AgentMemoryManager:
    """SQLite-backed episodic memory store for multi-session agent persistence."""

    def __init__(self, db_path: str = ":memory:"):
        self.conn = sqlite3.connect(db_path)
        self._init_db()

    def _init_db(self):
        with self.conn:
            self.conn.execute("""
                CREATE TABLE IF NOT EXISTS episodic_memory (
                    id INTEGER PRIMARY KEY AUTOINCREMENT,
                    thread_id TEXT NOT NULL,
                    step_number INTEGER NOT NULL,
                    action_type TEXT NOT NULL,
                    content TEXT NOT NULL,
                    timestamp TEXT NOT NULL
                )
            """)

    def record_step(self, thread_id: str, step_num: int, action_type: str, content: str) -> None:
        """Persists a new interaction step into the episodic memory thread."""
        record = MemoryRecord(
            thread_id=thread_id,
            step_number=step_num,
            action_type=action_type,
            content=content
        )
        with self.conn:
            self.conn.execute(
                "INSERT INTO episodic_memory (thread_id, step_number, action_type, content, timestamp) VALUES (?, ?, ?, ?, ?)",
                (record.thread_id, record.step_number, record.action_type, record.content, record.timestamp)
            )

    def retrieve_context(self, thread_id: str, limit: int = 5) -> str:
        """Retrieves recent episodic context formatted for prompt injection."""
        cursor = self.conn.cursor()
        cursor.execute(
            "SELECT step_number, action_type, content FROM episodic_memory WHERE thread_id = ? ORDER BY step_number ASC LIMIT ?",
            (thread_id, limit)
        )
        rows = cursor.fetchall()
        if not rows:
            return "No previous memory for this thread."

        formatted_lines = [f"[Step {r[0]} | {r[1]}]: {r[2]}" for r in rows]
        return "\n".join(formatted_lines)


if __name__ == "__main__":
    memory = AgentMemoryManager()
    session_thread = "session-audit-prod-2026"

    # Session 1: Agent performs discovery
    memory.record_step(session_thread, 1, "DISCOVERY", "Scanned VPC subnets: found 3 public subnets.")
    memory.record_step(session_thread, 2, "SECURITY_CHECK", "Identified open port 22 on bastion-host-01.")

    # Session 2: New prompt resuming work using thread_id
    retrieved_memory = memory.retrieve_context(session_thread)
    print("=== Injected Episodic Memory for New Execution ===")
    print(retrieved_memory)
```

**Developer Explanation:**
- **Libraries Used:** `sqlite3` for lightweight, atomic transactional storage, `datetime` for UTC timestamping, and `pydantic` for serialization.
- **How It Works:** Memory records are partitioned by `thread_id`. When resuming a workflow, the agent queries the store to retrieve its past decisions without storing megabytes of raw chat tokens.
- **Expected Output:** Contextually accurate past steps retrieved and formatted cleanly for system prompt injection.
- **Why This Approach:** Enables long-horizon multi-day tasks, session resumption across server restarts, and token-efficient memory recall.

### Example 6: "Plan-and-Execute" (Decoupled Architecture)
**Problem:** Monolithic ReAct agents lose their long-term objective when bogged down by extensive intermediate tool output.
**Solution:** Decouple the system into a high-level Planner that maintains overall state and a low-level Step Executor that operates in an isolated context window.

```python
from dataclasses import dataclass
from enum import Enum
from typing import Dict, List


class StepStatus(str, Enum):
    PENDING = "PENDING"
    IN_PROGRESS = "IN_PROGRESS"
    COMPLETED = "COMPLETED"
    FAILED = "FAILED"


@dataclass
class PlanStep:
    id: int
    description: str
    status: StepStatus = StepStatus.PENDING
    result: str = ""


class PlanAndExecuteOrchestrator:
    """Decoupled orchestrator maintaining global state while executing isolated steps."""

    def __init__(self, mission: str, steps: List[str]):
        self.mission = mission
        self.plan: List[PlanStep] = [
            PlanStep(id=i + 1, description=desc) for i, desc in enumerate(steps)
        ]

    def execute_step(self, step: PlanStep) -> str:
        """Isolated executor simulating specialized execution for a single task."""
        step.status = StepStatus.IN_PROGRESS
        print(f"\n[Executor] Running Step {step.id}: '{step.description}'...")

        # Mock execution logic per step
        if "isolate" in step.description.lower():
            output = "Target host 192.168.1.50 network interface detached."
        elif "dump" in step.description.lower():
            output = "Memory snapshot saved to s3://forensics-vault/dump-01.raw"
        elif "report" in step.description.lower():
            output = "Incident report #409 generated and dispatched to SOC."
        else:
            output = "Operation completed successfully."

        step.status = StepStatus.COMPLETED
        step.result = output
        return output

    def run_all(self) -> Dict[str, Any]:
        print(f"=== Starting Plan-and-Execute Orchestration ===")
        print(f"Mission: {self.mission}")

        for step in self.plan:
            result = self.execute_step(step)
            print(f"[Planner Updated] Step {step.id} {step.status.value}: {result}")

        return {
            "mission": self.mission,
            "all_completed": all(s.status == StepStatus.COMPLETED for s in self.plan),
            "step_results": {s.id: s.result for s in self.plan}
        }


if __name__ == "__main__":
    tasks = [
        "Isolate compromised VM host",
        "Dump volatile memory snapshot for forensic analysis",
        "Generate incident report and dispatch alert"
    ]
    orchestrator = PlanAndExecuteOrchestrator(
        mission="Contain and analyze security breach on host alpha",
        steps=tasks
    )
    summary = orchestrator.run_all()
    print(f"\nFinal Plan Execution Status: {summary['all_completed']}")
```

**Developer Explanation:**
- **Libraries Used:** Standard library `dataclasses`, `enum`, `typing`.
- **How It Works:** The Planner establishes the static roadmap. The Executor takes one step at a time, executes it with a clean context, and returns the condensed result to update the Planner's state.
- **Expected Output:** Deterministic progression through all steps with clear status tracking.
- **Why This Approach:** Eliminates catastrophic forgetting and keeps token costs manageable because the Executor does not carry the full history of previous steps.

### Example 7: Handling "Human Interrupts" (Governance & HITL)
**Problem:** Autonomous agents executing destructive operations (e.g., dropping database tables, deleting resources) introduce catastrophic risk.
**Solution:** Implement a Human-in-the-Loop (HITL) gate that pauses execution, issues a signed approval request token, and blocks until an administrator approves or denies the action.

```python
import uuid
from enum import Enum
from typing import Any, Dict, Optional
from pydantic import BaseModel, Field


class ApprovalStatus(str, Enum):
    PENDING = "PENDING"
    APPROVED = "APPROVED"
    REJECTED = "REJECTED"


class HumanInterruptRequest(BaseModel):
    """Payload representing a paused high-risk operation."""
    request_id: str = Field(default_factory=lambda: str(uuid.uuid4()))
    tool_name: str
    target_resource: str
    risk_level: str
    status: ApprovalStatus = ApprovalStatus.PENDING


class GovernanceEngine:
    """Manages pause-resume workflows for high-risk operations."""

    def __init__(self):
        self.pending_requests: Dict[str, HumanInterruptRequest] = {}

    def execute_with_guardrail(self, tool_name: str, resource_id: str, is_destructive: bool) -> Dict[str, Any]:
        """Executes safe tools immediately; pauses and requests human review for destructive tools."""
        if not is_destructive:
            return {"status": "executed", "result": f"Safely executed {tool_name} on {resource_id}."}

        # Create approval interrupt
        interrupt = HumanInterruptRequest(
            tool_name=tool_name,
            target_resource=resource_id,
            risk_level="CRITICAL"
        )
        self.pending_requests[interrupt.request_id] = interrupt

        return {
            "status": "PAUSED_WAITING_FOR_HUMAN",
            "request_id": interrupt.request_id,
            "message": f"Action '{tool_name}' on '{resource_id}' is high-risk and requires human authorization."
        }

    def resolve_interrupt(self, request_id: str, approved: bool) -> str:
        """Processes human decision and resumes or terminates the action."""
        if request_id not in self.pending_requests:
            return "Error: Request ID not found."

        req = self.pending_requests[request_id]
        if approved:
            req.status = ApprovalStatus.APPROVED
            del self.pending_requests[request_id]
            # Resume execution of destructive tool
            return f"Action APPROVED: Successfully executed '{req.tool_name}' on '{req.target_resource}'."
        else:
            req.status = ApprovalStatus.REJECTED
            del self.pending_requests[request_id]
            return f"Action REJECTED: Operation aborted for '{req.target_resource}'."


if __name__ == "__main__":
    gov = GovernanceEngine()

    # Step 1: Safe action executes immediately
    safe_run = gov.execute_with_guardrail("describe_clusters", "prod-cluster-01", is_destructive=False)
    print("Safe Tool:", safe_run)

    # Step 2: Destructive action is intercepted
    paused_run = gov.execute_with_guardrail("terminate_database_instance", "db-prod-primary", is_destructive=True)
    print("\nDestructive Tool Intercepted:", paused_run)

    # Step 3: Human reviews and grants authorization
    req_id = paused_run["request_id"]
    resolution = gov.resolve_interrupt(req_id, approved=True)
    print("\nHuman Resolution Result:", resolution)
```

**Developer Explanation:**
- **Libraries Used:** `uuid`, `enum`, `pydantic`.
- **How It Works:** The system categorizes actions into risk tiers. Destructive operations generate a pending `request_id` and pause execution. Execution only resumes when an external approval event is submitted.
- **Expected Output:** Clean separation of automated safe steps and intercepted high-risk actions awaiting human sign-off.
- **Why This Approach:** Prevents accidental data destruction and ensures compliance with organizational security policies (e.g., SOC2, ISO 27001).

### Example 8: Basic "Manager-Worker" Delegation
**Problem:** Single generalist agents underperform on complex multi-domain workflows requiring deep technical specialization (e.g., combining SQL optimization, security analysis, and frontend code).
**Solution:** Deploy a hierarchical multi-agent architecture where a Manager agent parses requests and routes sub-tasks to specialized Worker agents.

```python
from abc import ABC, abstractmethod
from typing import Dict, Any
from pydantic import BaseModel


class AgentTask(BaseModel):
    task_type: str
    payload: str


class WorkerAgent(ABC):
    """Abstract base class for specialized domain agents."""
    @abstractmethod
    def execute(self, payload: str) -> str:
        pass


class SecurityWorker(WorkerAgent):
    def execute(self, payload: str) -> str:
        return f"[SecurityWorker] Audited payload '{payload}': No hardcoded secrets or CVEs identified."


class DatabaseWorker(WorkerAgent):
    def execute(self, payload: str) -> str:
        return f"[DatabaseWorker] Analyzed query '{payload}': Added index on 'created_at' (estimated 4x speedup)."


class ManagerAgent:
    """Manager agent that dispatches incoming jobs to specialized domain workers."""

    def __init__(self):
        self.workers: Dict[str, WorkerAgent] = {
            "security": SecurityWorker(),
            "database": DatabaseWorker()
        }

    def dispatch(self, task: AgentTask) -> Dict[str, Any]:
        worker = self.workers.get(task.task_type.lower())
        if not worker:
            return {"status": "error", "message": f"No specialized worker registered for '{task.task_type}'."}

        worker_output = worker.execute(task.payload)
        return {
            "status": "success",
            "assigned_worker": task.task_type,
            "result": worker_output
        }


if __name__ == "__main__":
    manager = ManagerAgent()

    # Route a security task
    sec_job = AgentTask(task_type="security", payload="aws_access_key_id = os.getenv('AWS_KEY')")
    sec_result = manager.dispatch(sec_job)
    print(sec_result)

    # Route a database query optimization task
    db_job = AgentTask(task_type="database", payload="SELECT * FROM transactions WHERE created_at > '2026-01-01'")
    db_result = manager.dispatch(db_job)
    print(db_result)
```

**Developer Explanation:**
- **Libraries Used:** `abc` for interface definitions, `pydantic` for structured task exchange.
- **How It Works:** The Manager acts as an intelligent router, dispatching domain-specific payloads to dedicated `WorkerAgent` implementations that maintain their own tool sets and system prompts.
- **Expected Output:** Specialized workers execute their designated domain responsibilities and return structured results to the Manager.
- **Why This Approach:** Enables modularity, allows routing to smaller, cost-effective models for routine sub-tasks, and reduces prompt complexity.
